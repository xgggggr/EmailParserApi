# EmailParser API

Веб-сервис, который принимает файлы писем, разбирает их и раскладывает по категориям: спам, инциденты, мониторинг, доступы, оборудование, сбои ПО, документы, HR. Результат сохраняется в PostgreSQL, письма можно смотреть, фильтровать, перекладывать в другую категорию и считать статистику.

Это вторая версия моего консольного [EmailParser](https://github.com/xgggggr/EmailParser): раньше это был скрипт, который сортировал файлы из папки `inbox` по папкам категорий

**Стек:** Python 3.13 · FastAPI · SQLAlchemy 2 (async, asyncpg) · PostgreSQL 16 · Alembic · Pydantic v2 · pytest + anyio · Docker Compose · uv · ruff

---

## Быстрый старт (Docker)

Нужен только Docker.

1. Создайте в корне проекта файл `.env`:

   ```env
   POSTGRES_USER=emailparser
   POSTGRES_PASSWORD=придумайте_пароль
   POSTGRES_DB=emailparser
   DATABASE_URL=postgresql+asyncpg://emailparser:придумайте_пароль@127.0.0.1:5433/emailparser
   ```

2. Запустите:

   ```bash
   docker compose up --build
   ```

   Контейнер сам применит миграции и создаст 10 категорий.

3. Откройте http://localhost:8000/docs — там Swagger, из которого можно загрузить письма и вызвать любой эндпоинт.

Остановить: `docker compose down`. Остановить и удалить все данные: `docker compose down -v`.

## Запуск для разработки

Нужны [uv](https://docs.astral.sh/uv/) и Docker (для базы).

```bash
docker compose up -d db          # только PostgreSQL, на порту 5433
uv sync                          # зависимости
uv run alembic upgrade head      # таблицы и категории
uv run fastapi dev app/main.py   # сервер с автоперезагрузкой на http://127.0.0.1:8000
```

## Тесты

Тесты работают на отдельной базе `emailparser_test` и не трогают рабочие данные. Её нужно создать один раз:

```bash
docker compose exec db createdb -U emailparser emailparser_test
uv run pytest
```

- `tests/unit/` — парсер и классификатор, без базы и FastAPI;
- `tests/api/` — все эндпоинты через `httpx.AsyncClient`; перед каждым тестом таблицы пересоздаются, а зависимость `get_db` подменяется на тестовую базу.

Линтер: `uv run ruff check .`

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | Проверка, что сервис жив |
| `GET` | `/api/categories` | Список категорий |
| `GET` | `/api/stats` | Сколько писем в каждой категории |
| `POST` | `/api/emails/upload` | Загрузить пачку файлов `.txt` / `.json` |
| `POST` | `/api/emails` | Классифицировать письмо, переданное как JSON |
| `GET` | `/api/emails` | Список писем: фильтр `category`, пагинация `limit` (1–100) и `offset` |
| `GET` | `/api/emails/{id}` | Одно письмо |
| `PATCH` | `/api/emails/{id}` | Вручную поменять категорию |
| `DELETE` | `/api/emails/{id}` | Удалить письмо |

## Какие файлы принимаются

**`.txt` или файл без расширения.** Сначала заголовки, потом пустая строка, потом текст письма. Заголовки понимаются на английском, русском и транслитом, регистр не важен:

| Поле | Варианты заголовка |
|---|---|
| Тема | `Subject`, `Тема`, `Tema` |
| Отправитель | `From`, `От кого`, `Ot kogo` |
| Получатель | `To`, `Кому`, `Komu` |

```text
Тема: Срочно: сбой оплаты
От кого: monitoring@company.ru

Платёжный сервис не отвечает у всех клиентов.
```

Если заголовков нет, весь файл считается текстом письма.

**`.json`** — объект с ключами `subject`, `from`, `body`:

```json
{"subject": "Договор", "from": "buh@company.ru", "body": "Направляем акт на согласование"}
```

**Правила загрузки:**

- файл больше 1 МБ — ответ `413`;
- другое расширение (`.pdf`, `.png`, …) — ответ `415`;
- загрузка «всё или ничего»: если в пачке есть хотя бы один неподходящий файл, не сохраняется ни одно письмо из пачки;
- битый файл (некорректный JSON, текст не в UTF-8) — это не ошибка запроса: письмо сохраняется с категорией `corrupted` и `is_corrupted: true`.

## Категории и как работает классификатор

| Категория | Описание | Примеры ключевых слов |
|---|---|---|
| `spam` | Спам и фишинг | выиграли, акция, скидка, по ссылке |
| `critical_incidents` | Критические инциденты и сбои | инцидент, срочно, сбой, ошибка 500 |
| `monitoring` | Уведомления мониторинга | alert, healthcheck, uptime, warning |
| `software_failures` | Сбои программного обеспечения | после обновления, антивирус, excel |
| `access_control` | Запросы доступа и новые сотрудники | доступ, права, vpn, gitlab |
| `hardware` | Проблемы с оборудованием | принтер, ноутбук, ремонт, не включается |
| `documents` | Документооборот и финансы | договор, счёт, акт, оплат |
| `HR` | Кадровые вопросы и встречи | отпуск, больничный, созвон, корпоратив |
| `unknown` | Ни одно слово не совпало | — |
| `corrupted` | Файл не удалось прочитать | — |

Как выбирается категория:

1. Тема и текст приводятся к нижнему регистру.
2. Для каждой категории считается, сколько её ключевых слов встречается в теме и в тексте. Слово, найденное и там и там, даёт 2 очка.
3. Побеждает категория с наибольшим счётом. При ничьей решает приоритет: `spam` → `critical_incidents` → `monitoring` → `software_failures` → `access_control` → `hardware` → `documents` → `HR`.
4. Вместе с категорией сохраняются слова, по которым она выбрана (`matched_keywords`) — видно, почему письмо попало именно туда.

Если классификатор ошибся, категорию можно поправить через `PATCH /api/emails/{id}`.

## Структура проекта

```text
app/
├── main.py            # создание приложения, подключение роутеров
├── config.py          # настройки из .env (pydantic-settings)
├── database.py        # async-движок, сессии, зависимость get_db
├── models.py          # таблицы Category и Email
├── seed.py            # список категорий
├── routers/           # эндпоинты: emails, categories, stats, health
├── schemas/           # Pydantic-схемы запросов и ответов
└── logic/             # парсер и классификатор — обычный Python, без FastAPI
alembic/               # миграции
tests/
├── unit/
└── api/
Dockerfile
docker-compose.yml
```
